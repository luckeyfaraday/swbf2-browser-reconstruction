# Shared native and browser lighting lookups

Evidence ID: `BF2-SHARED-LIGHT-LOOKUP-002`. This is browser storage and shader-permutation work, not a newly recovered native lighting equation.

`web/src/source-dfg.js` now shares one `128 × 128 × 2` RGBA16F `DataArrayTexture` between three unchanged lookups:

| Lookup | Array placement | Sampling coordinates |
| --- | --- | --- |
| Original BF2 DFG RGB, generated by unchanged native shaders on WARP | Layer 0, original 128² domain | Original NdotV and perceptual roughness squared, half-texel clamp |
| Original BF2 IES half-float profile | Layer 0 alpha, original 128² domain | Original azimuth/elevation; repeat U, clamp V |
| Pinned Three runtime's existing fallback DFG RG16F | Layer 1, top-left 16² region | Clamp to original 16² texel centers, divide both coordinates by 8 |

All source/fallback half words are copied exactly. Source files and the Three fallback texture remain unchanged. The array has no mipmaps, color conversion, UV translation, or cross-layer interpolation. It occupies 262,144 bytes, excluding driver overhead. Unused layer-1 texels/channels are zero.

Three's fallback DFG is still required by its direct-light multiscattering compensation. Source ordinary materials use the recovered direct BRDF for proven native descriptors, but effect lights and unresolved descriptors retain the existing Three direct branch. The shared lookup preserves that fallback response instead of replacing or disabling it.

## Integration contract

Before constructing lighting adapters, call:

```js
const source = packSourceIesIntoDfg(assets.sourceDfg.texture, sourceIes.texture);
const shared = packThreeDfgIntoSourceLookup(source);
assets.sourceDfg.replaceLookupTexture(shared);
sourceIes.combinedDfgTexture = shared;
```

`packThreeDfgIntoSourceLookup` returns a new `DataArrayTexture`. It neither mutates nor disposes its input. `replaceLookupTexture` updates the existing prepared wrapper's getter, CPU sampler, diagnostics and disposal ownership, and disposes the old texture. Replacing after live shader compilation is not supported: existing shader uniforms would need explicit rebinding.

`createSourceDirectAdapter(...).finalizeShader(shader)` runs after `source-light-channels` has decorated and expanded `lights_fragment_begin`. It replaces exactly the two pinned Three `dfgLUT` accesses, removes that separate sampler, and switches the shared source declaration/helpers to `sampler2DArray`. Running this expansion before the channel decorator would prevent its source light gates and native calls from being installed.

## Reflection permutations and loading

`prepareSourceReflectionSampling` exposes `shaderMode` and `subscribeModeChange(callback)`. Proven ordinary materials use one of:

- `native`: original cube mip chain. `USE_ENVMAP` is undefined in the custom fragment so Three PMREM sampler/equations compile out.
- `pmrem`: existing PMREM path, with no raw-cube helper/sampler. This preserves the one-mip source exception; missing native mip levels are not invented.
- `none`: neither reflection sampler for explicitly uncovered regions.

Material program keys must include the current mode, and outer decorators must call prior cache-key functions dynamically. Mode changes invalidate affected materials. Cube swaps within the same mode only update shared uniforms.

Replacement downloads preserve the entire active cube/mip/direction tuple. Only a successful latest selection commits its cube and captured direction matrix. Failed/stale loads cannot mix a new basis with the previous cube. Null selection explicitly clears coverage. These are browser loading policies; native volume selection, overlap, box-frame construction and capture exposure remain unresolved.

The highest scoped material budget is now 11 material samplers + 1 probe sampler + 2 static-atlas samplers + 1 shared lookup + 1 reflection sampler = 16. Neither sampler reduction changes the recovered material equations or source payloads.

## Validation and rejected alternative

Run focused CPU tests from the repository root:

```powershell
node --test web/test/source-shared-lookup.test.js web/test/source-light-lookup.test.js web/test/source-reflection-sampling.test.js
```

The isolated GPU fixture is `web/test/source-shared-lookup-gpu-check.mjs` (run from `web`; coordinate GPU ownership before running). Its accepted report is `web/test-results/source-shared-lookup-gpu-check.json`:

- AMD Radeon 0x1636 through ANGLE/D3D11, fragment sampler limit 16.
- 98,577 cases: all original source and fallback texel centers, boundaries, deterministic random values, repeated IES azimuths, and 76,800 float32 ULP neighbors around filter-weight boundaries on both axes.
- 394,308 native DFG/IES scalar outputs and 197,154 Three fallback scalar outputs were bit-identical to the separate original textures. Maximum error was zero; the fixture requires exact equality.
- All 36 actual Three direct-light fallback renders were identical.
- Actual reflection/shared-lookup hooks compiled with 14 synthetic surface/probe/atlas samplers: native and PMREM modes each had exactly 16 active samplers; uncovered mode had 15. This proves isolated shader budget, not actual-map appearance or material routing.
- No console/page/GL errors. Full-map verification is run separately by the parent integration task.

The rejected 128 × 256 2D layout is retained in `web/test-results/source-shared-lookup-rejected-2d-rebase.json`. Although every source/fallback half word was preserved, translating Three V to `0.5 + v/16` lost float32 low bits and crossed hardware filtering boundaries. Twelve scalar outputs differed, maximum 0.0007171630859375. The runtime does not use that layout and no tolerance was relaxed. The accepted array layout avoids the translation structurally. GPU equality is established on the recorded hardware; other implementations were not tested.
