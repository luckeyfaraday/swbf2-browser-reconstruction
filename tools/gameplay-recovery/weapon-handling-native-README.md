# Native GunSway spread reconstruction

**BF2-WEAPON-HANDLING-NATIVE-001** binds the selected source GunSway configuration
to a bounded native path in the installed executable. No game process or GPU
was launched and no global Ghidra auto-analysis was used. The dedicated
headless project is under `exports/weapon-handling-native/ghidra-project`.

The source GunSwayData name locates type metadata and registration at
`0x142e47ab0`. Runtime registration `0x14165c120` pairs that type-info address
with factory `0x141659fe0`; the factory allocates0x1e0 bytes and invokes
constructor `0x141657d30`. The constructor writes the source-data pointer at
runtime+8 and vtable `0x143467b20`. Vtable slot3 is accepted-shot handling,
slot30 is the frame update, and slot32 obtains the spread transform.

Native metadata confirms GunSwayData.Dispersion at+0x18, Recoil at+0x20 and
PowerOfDispersionRandom at+0x3e8. The configuration resolver at `0x141659ab0`
reads flat `Dispersion[(pose*2+zoom)*4+action]`, each record24 bytes. This resolves
the previous named-structure versus array uncertainty on this path. Crouch and
Prone jumping/sprinting records in the array are valid selections even though
the named SDK structures omit them. Moving/sprinting interpolate all six
spread fields with the base record by clamped speed/recordedMaxSpeed.

The shot handler at `0x14165bc40` computes:

```text
azimuth = lerp(-pi, pi, U)
radiusRadians = powf(V, PowerOfDispersionRandom) * currentDispersion * pi / 180
pitch = sinf(azimuth) * radiusRadians
yaw   = cosf(azimuth) * radiusRadians
```

The retained PE constant bytes prove pi and1/180; import thunks resolve to
powf/cosf/sinf through their retained hint-name records. The .5 power used by
both rifles gives uniform area sampling in the small angular disk. It is not
the previous independently sampled square X/Y jitter. The source-local
transform at `0x14165ab30` is `Rx(pitch)*Ry(yaw)`; transforming native+Z yields
`(sin(yaw), -sin(pitch)*cos(yaw), cos(pitch)*cos(yaw))`.

The shot is sampled with existing dispersion and raises a pending-shot pulse.
The subsequent nonzero-dt frame update at `0x14165d2e0` adds IncreasePerShot
(with source first-shot factors under a separate guard), subtracts permitted
recovery, then clamps to MinAngle/MaxAngle. Recovery is linear rate*dt and
selects NoFireDecreasePerSecond when elapsed>=NoFireTimeThreshold; otherwise
it uses DecreasePerSecond. A runtime boolean at+0x1d4 suppresses recovery. The
frame wrapper increments elapsed and consumes the shot pulse exactly once.

Recoil is a separate native kernel at `0x14165d570`. It also converts source
amplitudes by pi/180 and includes time-squared recovery, modifier factors and
optional camera spring composition. It is recorded but **not** applied by this
spread adapter, so the recovered additive firing animation is not doubled.

`web/src/weapon-handling.js` now provides:

```js
const spread = createWeaponSpread(handlingDocument, weaponId, {random: () => ctx.rand()});
spread.update(dt, {
  pose: 'stand',             // stand, crouch, prone
  aiming: false,
  movement: 'moving',        // base, moving, jumping, sprinting
  movementFraction: 0.5,    // clamped actual speed / chosen maximum speed
  firing: true,
});
const shot = spread.fire(); // only after the real weapon accepts a shot
// shot.pitch/yaw are radians; shot.localDirection is native source-local +Z.
spread.reset();             // spawn/weapon reset; never advance while dead
```

Update the state once per simulation tick and call fire only at the accepted
shot point. Native shot flags are booleans; more than one accepted shot between
updates is outside this adapter's scheduling contract. The existing `selectWeaponHandling`
function remains a raw named-field snapshot and does not silently change camera
layers or apply handling behavior.

Remaining adapter inferences are explicit: browser actor states and motion
fractions; held trigger mapped to the native recovery-suppression flag (its
caller is not traced); first-shot guard; initial/reset state at source minimum
(equivalent to the first native clamp); browser random stream and event order;
JS double precision/libm differences; native+Z basis mapping into the browser
firing ray. Pose-transition penalties, native suppression, conditional unlock
modifiers, native RNG seeding and camera composition are excluded.

Reproduce the retained byte evidence with
`python tools/gameplay-recovery/weapon-handling-native-evidence.py`. Source
configuration remains generated by `weapon-handling-build.py`. Test with
`cd web; node --test test/weapon-spread.test.js test/weapon-handling.test.js`.
The tests cover native metadata/constants/import links, all24 source states,
motion interpolation, uniform radial area, independent Three matrix rotation,
accepted-shot ordering, clamp/recovery thresholds and state reset/isolation.
